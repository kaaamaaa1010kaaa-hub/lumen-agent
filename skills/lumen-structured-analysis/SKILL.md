# 分析を構造化する

論点が枝分かれする分析では、1本の長い文章にせず、1つの概念・仮説・根拠・結論を1つの `[[ノード]]` に書き出す。重複や矛盾に気づきやすく、読み手も分岐を追える。

1. ノードは1つにつき1テーマ。例: `[[認証方式/セッション]]`、`[[認証方式/JWT]]`、`[[比較/セキュリティ]]`。
2. 関係はノードの直後に書く。
   - `-> [[Node]]` 発展・帰結
   - `<- [[Node]]` 前提・根拠
   - `<-> [[Node]]` 相互参照・類似
   - `x-> [[Node]]` 反駁・競合
3. 対立する仮説や代替案は、独立したノードとして並べる。最後に統合ノード（例: `[[MOC/結論]]`）で着地し、どれを採りどれを退けたかと、その理由を書く。退けた側を黙って消さない。
4. 関係が複雑になって図のほうが伝わるときは、` ```mermaid ` の `graph TD` で全体を1枚に示してよい。
5. 単純な一問一答、短いコード修正、事実確認、比較表で足りる比較、唯一解のある技術的な質問には使わない。通常の Markdown のままでよい。
6. 複数の実行方針を、成功確率・リスク・コストで定量比較してから選びたいときは、ノードを並べるより simulate_parallel_scenarios ツール（接続されていれば）を使う。
